## ضوابط متابعة إلزامية

1. لا تبدأ نقل الملفات قبل اكتمال المرحلة 1 ومراجعة نتائجها.
2. لا تُنشأ فروع جديدة؛ العمل على `main` وفق تعليمات المستخدم الحالية.
3. لا تُحذف ملفات أو تُغيّر أسماءها لمجرد أنها تبدو غير مستخدمة.
4. قبل أي نقل، افحص مراجع HTML وJS وCSS وJSON وملفات البناء وGitHub Actions وVercel وService Worker والروابط المباشرة.
5. لا تغيّر المحتوى القانوني أو معرّفات الأسئلة والبيانات إلا لضرورة مثبتة وموافقة واضحة.
6. لا تُضعف Firebase Authentication أو قواعد Firestore/Storage.
7. لا تضف طبقات CSS أو أكواد التفافية لتجاوز المشكلة الأصلية.
8. حافظ على التحميل الجزئي للبيانات، وSEO، وsitemap، وPWA، والنشر الحالي.
9. بعد كل مرحلة، سجّل الملفات المتأثرة، والفحوص التي نُفذت فعلًا ونتائجها، والمشكلات المفتوحة، والخطوة التالية.
10. إذا تعذر التحقق من نتيجة ما، اذكر ذلك صراحة ولا تصفها بأنها ناجحة.

## سجل الجلسات والتغييرات

### بدء المتابعة
- تم تثبيت خطة متابعة بمراحل وبشروط إكمال واضحة.
- تم تأكيد وجود ملفات توثيق سابقة ذات صلة، منها:
  - `docs/architecture/MIZAN_PROJECT_ORGANIZATION_RULES.md`
  - `docs/architecture/ARCHITECTURE_REORGANIZATION_PLAN.md`
  - `docs/architecture/JS_DEPENDENCY_MAP.md`
  - `scripts/build-pages-bundle.sh`
  - `scripts/validate-static-project.mjs`
- تم إنشاء هذا السجل على `main` في Commit `0e2a8f6123e9999c2998780739fe3454701c23e4`.
- جرى فحص شجرة المستودع عند بدء الجرد: 347 عنصرًا في الشجرة، منها 66 ملفًا في الجذر؛ أبرز المسارات الحالية هي `.github/`, `api/`, `assets/`, `data/`, `docs/`, `engine/`, `icons/`, `reports/`, و`scripts/`.
- توجد خريطة اعتماديات JavaScript تصف ترتيب التحميل في `index.html)، لكنها تنص على أنها خريطة ساكنة ولا تغني عن اختبار المتصفح.
- `scripts/build-pages-bundle.sh` يبني حزمة GitHub Pages من ملفات HTML/JS/CSS/manifest الموجودة في الجذر، ثم ينسخ `engine/`, `icons/`, `data/`, و`assets/`. لذلك نقل أي ملف تشغيل من الجذر يتطلب تعديلًا متزامنًا ومتحققًا لآلية البناء وكل المراجع.
- `scripts/validate-static-project.mjs` يفحص JSON ومراجع الأصول المحلية ورموز تصميم Mizan، بينما سير عمل `.github/workflows/validate-project.yml` يفحص أيضًا صياغة JavaScript وبناء حزمة Pages.
- **ملاحظة تحتاج قرارًا/تحققًا قبل التنفيذ:** سير عمل التحقق الحالي يذكر `pull_request` إلى `main` و`workflow_dispatch`، ولا يظهر فيه trigger من نوع `push`. بما أن سياسة المشروع الحالية هي التعديل مباشرة على `main`، يجب تحديد آلية تشغيل التحقق بعد تغييرات `main` دون تغييرها قبل مراجعة سير العمل كاملًا.
- **ملاحظة مهمة عن PWA:** لم يظهر ملف `service-worker.js` ضمن ملفات الجذر الحالية في الشجرة المفحوصة. و`platform-bootstrap.js` يحتوي على منطق إلغاء تسجيل Service Workers المسجلة. يجب فهم سبب ذلك والتحقق من سلوك PWA الحالي قبل أي تغيير؛ لا نفترض أن Service Worker فعّال حاليًا.
- إعداد `vercel.json` يعيد توجيه `/sitemap.xml` إلى `/api/sitemap` و`/pulpit/:id` إلى `/api/article?id=:id`؛ يجب الحفاظ على هذه المسارات أثناء التنظيم.
- لم تُشغّل اختبارات محلية أو اختبارات متصفح في هذه الخطوة؛ النتائج أعلاه مراجعة ساكنة لمحتوى المستودع فقط.
- لم يُسجّل بعد إكمال الجرد الفعلي؛ المرحلة 1 ما زالت قيد التنفيذ.
