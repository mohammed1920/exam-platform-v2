# خريطة اعتماديات JavaScript — منصة ميزان

> هذه خريطة أولية مبنية على ترتيب تحميل السكربتات في `index.html` وعلى المراجع العامة `window.*` داخل الملفات. ليست إثباتًا نهائيًا لكل اعتماد وقت التشغيل؛ تُستكمل بتحليل الدوال والأحداث قبل نقل أي كود أو دمج ملفات.

## قواعد التعامل

- لا تغيّر ترتيب السكربتات في `index.html` قبل التحقق من كل اعتماد مباشر وغير مباشر.
- لا تحذف ملفًا لمجرد صغر حجمه أو عدم وضوح وظيفته؛ تحقّق من مستمعي الأحداث والتحميل الديناميكي أولًا.
- عند نقل دالة إلى وحدة جديدة، أبقِ الواجهة العامة الحالية أو حدّث جميع المستهلكين في نفس التغيير.
- ملفات البيانات `data/**/chapter_N.json` لا تُحمّل دفعة واحدة؛ حافظ على التحميل عند الحاجة.
- لا تُعدّل تصميم الكتب ثلاثي الأبعاد ضمن أعمال تنظيم الواجهة.

## ترتيب تحميل السكربتات في `index.html`

1. مكتبة Lottie الخارجية.
2. Firebase App Compat وFirebase Auth Compat.
3. `firebase-auth.js` — يوفّر `window.publicAuth`.
4. `engine/examEngine.js` — يوفّر `window.examEngine`.
5. `book-icons.js`.
6. `app.js` — يوفّر `window.app`، وهو أكبر ملف تطبيق حاليًا.
7. `global-search.js` — يوفّر `window.globalSearch`.
8. `home.js` — يوفّر دوال تحميل المنبر ودليل المحامين والعرائض، ويضيف سلوكًا إلى `window.app`.
9. `platform-sidebar.js` — يستهلك واجهات التنقل وتحميل الأقسام.
10. `user-dashboard.js` — يوفّر `window.studentDashboard`.
11. `student-account-patch.js` — يستمع إلى تغيّر حالة المصادقة؛ لا يُدمج أو يُحذف قبل التحقق من توقيت الحدث.
12. `wrong-answers-limit.js`.
13. `wrong-answers-retest.js`.
14. `platform-header-fix.js`.
15. `theme.js` — يوفّر `window.platformTheme`.
16. `firebase-admin-panel.js` — يوفّر `window.firebaseAdminPanel`.
17. `mizan-pulpit-admin.js`.

## ملفات CSS ذات الأولوية للمراجعة

- `mizan-colors.css`: مرجع الألوان المركزي.
- `mizan-design-tokens.css`: رموز المسافات والحواف والحركة.
- `style.css`: يحتوي أيضًا على تصميم الكتب ثلاثي الأبعاد، لذا يجب عزل هذا الجزء قبل أي تنظيف شامل.
- `theme.css` و`mizan-unified-theme.css`: كلاهما محمّل في الصفحة الرئيسية؛ يجب تحليل التداخل والأولوية قبل حذف أو دمج أي منهما.
- `student-ui-fixes.css`: طبقة إصلاحات إضافية؛ لا تُحذف بناءً على الاسم فقط.

## الخطوات التالية

1. حصر تعريفات الدوال والأحداث في `app.js` وتجميعها حسب المسؤولية دون نقلها بعد.
2. تتبّع الاعتماديات الخاصة بالاختبارات، وتحديد الإجابات، والبحث، والصلاحيات، والتنقل.
3. مراجعة تداخل طبقات CSS مع الحفاظ على الشكل الحالي.
4. تنفيذ إعادة التنظيم في دفعات محددة على فرع العمل.
5. بعد اكتمال دفعات التنظيم، إجراء فحص شامل للبناء والسلوك والمظهر على الموقع كله قبل الدمج أو النشر.

## تحديث — فصل بطاقات التواصل

- أُنشئ `contact-info.js` لتولي تحميل بيانات `data/contact.json` وعرض بطاقات الاتصال والروابط الاجتماعية.
- أُبقيت واجهتا `loadContactInfo()` و`renderContactInfo(data)` داخل `ExamApp` كواجهتين تفويضيتين لتقليل أثر التغيير على المستهلكين.
- يُحمّل `contact-info.js` قبل `app.js` في `index.html`.
- هذا فصل أولي لوحدة مستقلة؛ ما زال مطلوبًا اجتياز فحص الصياغة والتحقق من ظهور بطاقات التواصل في المعاينة قبل اعتماد المرحلة.

## تحديث ترتيب التحميل بعد فصل الوحدات

الترتيب الحالي في `index.html` يتضمن الوحدات التالية قبل `app.js`:

- `contact-info.js` — تحميل وعرض بطاقات التواصل.
- `exam-drafts.js` — تخزين مسودات الاختبارات وترحيل المفتاح القديم.
- `question-sharing.js` — إنشاء الروابط وبطاقات مشاركة الأسئلة.
- `app.js` — يبقى واجهة التطبيق الرئيسية، وتفوض إليه الواجهات الجديدة عبر `window.MizanContactInfo` و`window.MizanExamDrafts` و`window.MizanQuestionSharing`.

ملفات الواجهة والإدارة المفصولة:

- `platform-header.css` يملك قواعد الهيدر؛ `platform-header-fix.js` يركّب شعار Lottie فقط.
- `platform-bootstrap.js` يحتوي تنظيف تسجيل Service Worker القديم وسلوك التثبيت وعدّاد الزيارة، ويُحمّل في نهاية الصفحة.
- `admin.css` و`admin.js` و`admin-theme.js` تفصل تنسيقات لوحة الإدارة ومنطقها ومبدّل الثيم.
- بقيت شيفرتا التهيئة الصغيرتان في رأس `index.html` مضمنتين عمدًا للحفاظ على توقيت التهيئة قبل الرسم.
