# الدليل المعماري الموحد لمنصة ميزان

> المرجع المركزي لفهم بنية المشروع وملكية الملفات. هذا الدليل يصف البنية الحالية، بينما تبقى تعليمات التنفيذ والفحوص التفصيلية في `DEVELOPMENT.md`.

## 1. البنية العامة

- `index.html` و`admin.html`: واجهات التطبيق العامة والإدارة.
- `assets/shared/`: الموارد المشتركة بين أكثر من قسم.
- `assets/features/<section>/`: ملفات كل قسم وواجهته.
- `engine/`: محرك الاختبارات.
- `data/`: الكتب والأسئلة والقوانين وبيانات الأقسام.
- `api/`: واجهات Vercel.
- `scripts/`: التحقق والبناء والفهرسة والصيانة.
- `.github/workflows/`: التحقق والنشر والأتمتة.
- `docs/`: توثيق الأنظمة المتخصصة فقط، لا تُنشأ تقارير جرد مؤقتة متكررة دون حاجة.

## 2. نظام التصميم المركزي

توجد ثلاثة ملفات مركزية فقط، ولكل ملف مسؤولية واضحة:

| الملف | الملكية |
|---|---|
| `assets/shared/css/mizan-colors.css` | لوحة الألوان، التدرجات، وألوان الوضعين النهاري والليلي |
| `assets/shared/css/mizan-design-tokens.css` | المسافات، الأحجام، الخطوط، الحواف، الظلال، والحركة |
| `assets/shared/css/mizan-unified-theme.css` | تطبيق المظهر الموحد على الموقع، بما فيه الهيدر والقائمة الجانبية والبطاقات والعناصر المشتركة |

لا تُنشأ ملفات ثيم أو هيدر أو قائمة جانبية مستقلة. لا تكرر تعريف الألوان أو المظهر في ملفات الأقسام؛ تبقى فيها قواعد البنية والتخطيط والسلوك الخاص بالقسم. ملف `style.css` يحتفظ بتنسيقات الاختبارات وتصميم الكتب ثلاثية الأبعاد، ولا يُعاد تصميم بطاقات الكتب ضمن توحيد الهوية.

## 3. ملكية JavaScript

- `assets/shared/js/`: الخدمات العامة والتهيئة والمصادقة والتنقل والثيم والبحث.
- `assets/features/<section>/js/`: منطق القسم المحدد.
- `engine/examEngine.js`: منطق الاختبارات وتحميل البيانات المطلوبة عند الحاجة.
- لا تنقل ملفًا أو تحذفه قبل تتبع مراجع HTML والتحميل الديناميكي والواجهات العامة مثل `window.*`.

## 4. البيانات

- `data/books.json`: فهرس الكتب الرئيسي.
- `data/<book-id>/chapter_N.json`: أسئلة الفصول.
- حافظ على `uid` و`id` للأسئلة وعلى بنية البيانات والتوافق مع النتائج والمسودات.
- لا تحمّل جميع الكتب والأسئلة دفعة واحدة؛ التحميل يكون عند الحاجة.
- ملفات الأقسام داخل `data/` قد تملك README متخصصًا عندما يشرح مخطط بيانات لا ينطبق على بقية المنصة.

## 5. البناء والنشر

- سكربت الحزمة: `scripts/build-pages-bundle.sh`.
- فحص الأصول: `scripts/validate-static-project.mjs`.
- نشر GitHub Pages: `.github/workflows/update.yml`.
- تحقق من قائمة `required_files` عند إضافة أو حذف ملف منشور، ولا تُبقِ فيها مسارات قديمة بعد حذف الملفات.
- النشر على Vercel وGitHub Pages مساران منفصلان؛ نجاح أحدهما لا يثبت نجاح الآخر.

## 6. قواعد التعديل

1. العمل على `main` فقط، دون إنشاء فروع.
2. أصلح السبب الجذري ولا تضف طبقات ترقيع أو ملفات مكررة.
3. لا تحذف ملفًا قبل فحص جميع مراجع التحميل والاستخدام.
4. لا تغيّر محتوى قانونيًا أو معرفات أو قواعد أمان دون طلب ومراجعة.
5. لا تدّعِ نجاح فحص أو نشر لم يتم التحقق منه.
6. اختبر الهاتف والحاسوب والوضعين الفاتح والداكن عند تغيير الواجهة.

## 7. الوثائق التي تبقى مستقلة

- `README.md`: تعريف المشروع وطريقة تشغيله وإضافة البيانات.
- `DEVELOPMENT.md`: خطوات التطوير والفحوص وملكية الملفات.
- `SECURITY.md`: متطلبات الأمان والخصوصية.
- `docs/PROCEDURES_CATALOG.md`: مخطط فهرس الإجراءات في Firebase.
- `data/judicial-institute/README.md`: مخطط ملفات أسئلة المعهد القضائي.
- `docs/architecture/PROJECT_REORGANIZATION_STATUS.md`: سجل تاريخي لتغييرات إعادة التنظيم؛ يُحدّث عند حدوث تغيير معماري كبير، وليس لكل تعديل صغير.

تُحذف تقارير الجرد المؤرخة أو تقارير التدقيق المؤقتة عندما تصبح معلوماتها ممثلة في هذا الدليل أو في الكود الحالي. لا تُحذف وثائق الأمان أو مخططات بيانات الأقسام لمجرد تقليل العدد.
