# ⚖️ ميزان | المنصة القانونية العراقية

**ميزان.. حيث يُقاس الفهم القانوني بدقة.**

منصة عراقية للتعلم والمراجعة القانونية والاختبارات التفاعلية، مع حسابات الطلاب وأقسام الخدمات القانونية. الواجهة مبنية بـ HTML وCSS وJavaScript، وتستخدم ملفات JSON للكتب والفصول مع تحميل البيانات عند الحاجة.

## 🎯 الفكرة الأساسية

بدلاً من إنشاء مستودع لكل كتاب (كما في النسخة الأولى)، تجمع هذه النسخة **كل الكتب والفصول والأسئلة في مستودع واحد** باستخدام ملفات JSON منظمة، مما يجعل الإدارة أسهل والصيانة أقل تعقيداً.

## 🏗️ المعمارية

```
Frontend (HTML + CSS + JS)
    ↓
Exam Engine (JavaScript)
    ↓
Data Layer (JSON Files)
```

## 📚 نظام البيانات

### `data/books.json`
هو المصدر الرئيسي لقائمة الكتب. أضف سجل الكتاب بمعرّف مجلد البيانات نفسه؛ يتم تحديث عدد الفصول بواسطة سير عمل الصيانة اعتمادًا على ملفات الفصول الموجودة فعليًا.

```json
[
  {
    "id": "law_commercial",
    "title": "القانون التجاري",
    "author": "مستشار قانوني",
    "description": "دراسة شاملة في القانون التجاري",
    "icon": "scale"
  }
]
```

### ملفات الفصول (`chapter_N.json`)
تُحفظ داخل `data/<book-id>/`. الحقول الأساسية للسؤال هي `id` و`question` و`options` و`answer`، مع `uid` ثابت وفريد و`explanation` اختياري.

```json
{
  "id": "law_commercial_ch1",
  "book_id": "law_commercial",
  "chapter": 1,
  "title": "مقدمة",
  "questions": [
    {
      "id": 1,
      "question": "ما المقصود بالمصدر القانوني؟",
      "options": ["الخيار الأول", "الخيار الثاني", "الخيار الثالث"],
      "answer": 0,
      "explanation": ""
    }
  ]
}
```

عند إضافة سؤال جديد، لا تغيّر `id` أو `uid` للأسئلة الموجودة. سير عمل الصيانة يضيف `uid` المفقود عند الحاجة؛ لا تستبدل `answer` بالحقل القديم `correct`.

## ⚙️ طريقة العمل

1. **تحميل الكتب:** عند فتح الموقع، يتم تحميل قائمة الكتب من `books.json`
2. **اختيار كتاب:** المستخدم يختار كتاباً من القائمة
3. **اختيار فصل:** يتم عرض فصول الكتاب المختار
4. **بدء الاختبار:** المستخدم يبدأ الاختبار لفصل معين
5. **الإجابة على الأسئلة:** يتم عرض الأسئلة واحداً تلو الآخر مع تغذية راجعة فورية
6. **عرض النتائج:** بعد انتهاء الاختبار، يتم عرض النتائج والدرجة
7. **مراجعة الأخطاء:** المستخدم يمكنه مراجعة الأسئلة التي أخطأ فيها

## 🚀 التشغيل المحلي

### المتطلبات
- متصفح ويب حديث
- خادم ويب محلي (اختياري لكن مفضل)

### بدء التشغيل

#### الطريقة 1: استخدام Python
```bash
cd exam-platform-v2
python -m http.server 8000
```

ثم افتح المتصفح على: `http://localhost:8000`

#### الطريقة 2: استخدام Node.js
```bash
cd exam-platform-v2
npx http-server
```

#### الطريقة 3: فتح الملف مباشرة
يمكنك فتح ملف `index.html` مباشرة في المتصفح (لكن قد لا تعمل بعض الميزات بسبب قيود CORS).

## 🎨 المميزات

- ✅ **مستودع واحد:** كل الكتب والأسئلة في مكان واحد
- ✅ **سهل التعديل:** تعديل ملفات JSON فقط دون الحاجة لتعديل الكود
- ✅ **تصميم حديث:** واجهة مستخدم جميلة وسهلة الاستخدام
- ✅ **دعم اللغة العربية:** كامل الدعم للغة العربية
- ✅ **مؤقت:** تتبع الوقت المستغرق في الاختبار
- ✅ **تغذية راجعة فورية:** عرض الإجابة الصحيحة والشرح فوراً
- ✅ **مراجعة الأخطاء:** إمكانية مراجعة الأسئلة الخاطئة
- ✅ **حفظ النتائج:** حفظ النتائج في localStorage
- ✅ **تصميم مستجيب:** يعمل على جميع الأجهزة (موبايل، تابلت، ديسكتوب)

## 🧠 محرك الاختبارات (Exam Engine)

يوفر محرك الاختبارات الوظائف التالية:

- تحميل الكتب والفصول
- تتبع الأسئلة والإجابات
- حساب الدرجات
- حفظ النتائج في localStorage
- استخراج الأسئلة الخاطئة

## 📱 تطبيق الويب التقدمي (PWA)

تدعم المنصة التثبيت على الشاشة الرئيسية من المتصفح، مع واجهة متجاوبة للهاتف والحاسوب. **التخزين المؤقت للعمل دون اتصال ليس مفعّلًا حاليًا**؛ ويزيل كود التهيئة تسجيلات Service Worker القديمة، لذلك لا ينبغي افتراض أن الكتب أو الأسئلة متاحة دون إنترنت.

## ✅ الميزات الحالية

- تصفح الكتب والفصول وتشغيل الاختبارات ومراجعة الإجابات.
- إعداد اختبار مخصص من الكتب المتاحة وتحميل الأسئلة المطلوبة فقط.
- البحث في أقسام المنصة، مع إتاحة نتائج الأسئلة وفق حالة تسجيل الدخول.
- حفظ مسودة الاختبار واستئنافها، وحفظ سجل الطالب محليًا.
- مراجعة الأسئلة الخاطئة وإعادة اختبارها.
- تسجيل دخول الطلاب ولوحات حساب الطالب، مع لوحة إدارة منفصلة.
- أقسام دليل المحامين والعرائض والطلبات ومنبر ميزان، مع تحميل بعض الأقسام عند الطلب.
- إدارة بيانات التواصل من لوحة الإدارة، وثيم ليلي ونهاري.

## 📖 كيفية إضافة كتاب جديد

1. أضف مجلدًا في `data/` بمعرّف ثابت للكتاب.
2. أضف ملفات `chapter_N.json` مع مخطط السؤال الحالي الموضح أعلاه.
3. أضف سجل الكتاب إلى `data/books.json` باستخدام المعرّف نفسه.
4. اترك تحديث عدد الفصول لسير عمل الصيانة، وتحقق من تقرير سلامة البيانات قبل اعتماد التغيير.

مثال:
```json
{
  "id": "law_commercial",
  "title": "القانون التجاري",
  "author": "مستشار قانوني",
  "description": "شرح شامل للقانون التجاري",
  "icon": "scale"
}
```

## 📖 كيفية إضافة أسئلة جديدة

1. افتح ملف الفصل المطلوب داخل `data/<book-id>/chapter_N.json`.
2. أضف سؤالًا بمفاتيح `id` و`question` و`options` و`answer`، ويمكن إضافة `explanation`:

```json
{
  "id": 6,
  "question": "السؤال الجديد؟",
  "options": ["الخيار 1", "الخيار 2", "الخيار 3"],
  "answer": 0,
  "explanation": ""
}
```

## 🔧 التخصيص

### تغيير الألوان والتصميم

- عدّل ألوان الهوية المركزية في `mizan-colors.css`.
- عدّل رموز التصميم المشتركة مثل الحواف والحركة في `mizan-design-tokens.css`.
- لا تستخدم `style.css` كمصدر للألوان العامة؛ فهو يحتوي تصميم بطاقات الكتب ثلاثية الأبعاد الذي يجب الحفاظ عليه دون تغيير.
- افحص ترتيب التحميل والتباين في الوضعين الليلي والنهاري قبل اعتماد أي تغيير.

### تغيير الخطوط
عدّل الخطوط في `style.css`:

```css
body {
  font-family: 'Cairo', 'Segoe UI', Tahoma, sans-serif;
}
```

## 🔐 الأمان وسلامة البيانات في الإصدار الحالي

- `data/books.json` هو **مصدر الحقيقة لقائمة الكتب**؛ الأتمتة لا تحذف كتابًا بسبب غياب مجلد أو فصل.
- الأتمتة تحدّث `chapters` فقط من الملفات الفعلية، وتضيف هوية مفقودة للسؤال دون تعديل نصه أو إجابته أو شرحه.
- كل سؤال الآن يملك `uid` ثابتًا وفريدًا، مع الحفاظ على `id` القديم للتوافق.
- تعديل السؤال في لوحة الإدارة يحافظ على `id` و`uid` و`explanation` وجميع الحقول غير التحريرية.
- محرر الأسئلة يدعم عدد الخيارات الموجود فعليًا ولا يفرض 4 خيارات على سؤال قديم يحتوي 5 أو أكثر.
- يوجد فحص `integrity_check.py` غير هدّام يولّد `reports/data_integrity_report.json` بالأمور التي تحتاج مراجعة بشرية.
- يوجد `validate_project.py` يمنع النشر إذا ظهرت أخطاء بنيوية قاتلة.
- GitHub Actions لا تستخدم `-X ours` لدمج تغييرات متنافسة؛ تستخدم `rebase` وconcurrency لمنع الكتابة فوق تغييرات أحدث.
- Workflow النشر يضمّن `admin.html` كواجهة ثابتة؛ يمكن الوصول إلى الصفحة عبر الرابط المباشر، ولا تُعدّ مخفية أو وسيلة مصادقة بحد ذاتها. ملفات Python وتقارير الفحص وإعدادات CI لا تُنسخ إلى مجلد النشر.
